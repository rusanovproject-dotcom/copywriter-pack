## 1.0.5 — 2026-05-05

**Двухуровневая память: индекс проектов + выжимка ЦА в каждом проекте.**

В 1.0.4 копирайтер сохранял всё в одном `audience-map.md` рядом с собой. Проблема: (1) огромные JTBD-файлы (1500-5000 строк) либо целиком в выжимке, либо лениво — оба варианта плохие; (2) непонятно как работать с несколькими проектами.

В 1.0.5 архитектура двухуровневая:

```
office/agents/copywriter/audience-map.md       ← ИНДЕКС проектов (~30 строк)
projects/<slug>/audience/audience-snapshot.md  ← ВЫЖИМКА (в каждом проекте своя, ~80 строк)
```

**Что меняется в работе:**

- При первом запросе копирайтер сканирует `projects/*/`, спрашивает «над каким работаем?» если проектов несколько, **собирает snapshot прямо в проекте** (контекст проекта 3 строки + 3-5 сегментов + топ-3 болей на сегмент + 5-10 дословных цитат + core-offer + якоря в полных файлах)
- Дальше при каждом маркетинговом тексте читает **только snapshot** активного проекта (~80 строк, быстро)
- В полные файлы JTBD ныряет **только для лендингов/лонгридов** и только в нужную секцию по якорю — не читает 1500 строк целиком
- Несколько проектов = несколько snapshot файлов в каждом проекте + индекс с пометкой «активный»
- Переключение по триггеру «работаем над [проект]»
- Пересборка по «обнови snapshot» / «у меня поменялась ЦА» / при появлении новых файлов в `projects/<slug>/audience/`

**Файлы:**

- `audience-map.md.template` — переписан как лёгкий **индекс проектов** + шаблон snapshot (для копирайтера, как собирать)
- `core.md` — переписан pipeline (6 шагов: чтение индекса → определение проекта → сборка snapshot если новый → работа из snapshot → триггеры пересборки → триггеры переключения)
- `install.md` post-install: явно сказано про двухуровневую схему
- `README.md`: «один раз сканирует — дальше молча» переписан под snapshot-в-проекте

**Что в проекте создаётся:**

- `projects/<slug>/audience/audience-snapshot.md` — рабочая выжимка копирайтера. Лежит в проекте, не в копирайтере. Используется и копирайтером и (потенциально) другими агентами.

## 1.0.4 — 2026-05-05

**Карта ЦА: один раз сканируем офис, дальше работаем молча.**

Раньше (1.0.1-1.0.3) копирайтер при каждом маркетинговом запросе шерстил офис заново и переспрашивал у пользователя «где ЦА?». Теперь — **сканирует один раз** при первом запросе, запоминает пути в `audience-map.md`, дальше читает оттуда автоматически.

- Новый файл: `audience-map.md.template` — шаблон карты ЦА (4 секции: анализ ЦА / цитаты покупателей / оффер / позиционирование). Копируется в `office/agents/copywriter/audience-map.md` при установке.
- `core.md`: переписан pipeline для маркетинговых текстов:
  - **Шаг 1:** прочитать `audience-map.md`
  - **Если `status: filled`** — читать файлы по путям, работать молча
  - **Если `status: empty`** — просканировать офис одним заходом (`projects/*/audience/`, `hub/marketing/`, `knowledge/audience/`, `projects/*/products/`), показать пользователю что нашёл, после подтверждения сохранить пути в карту, поменять `status: filled`
  - **Если ничего не нашёл** — спросить 3 вопроса в чате, сохранить в `quick-snapshot.md`, прописать путь в карту
  - **Триггер пересборки:** «пересобери карту аудитории» / «обнови audience-map»
- `install.md`: `audience-map.md.template` → `audience-map.md` в файлах установки (preserve_if_exists). Manual install обновлён.
- `install.md` post-install: явно сказано «копирайтер один раз просканирует офис, запомнит пути, дальше работает молча».

- `skills/stop-slop/SKILL.md` переписан под двуязычный формат:
  - Алгоритм 3 фаз (ДЕТЕКЦИЯ → ПЕРЕПИСЫВАНИЕ → ФИНАЛ)

## 1.0.0 — 2026-05-05

**Первый релиз публичного пакета копирайтера для офисов учеников.**

### Архитектура
- **Голос + регистр** — копирайтер пишет напрямую по контексту: `voice.md` (личный голос автора) + один из 5 регистров `voice-*.md`
- **Без write-* скиллов** — все типы текста (post / тред / крео / серия / лендинг / лонгрид) пишутся по контексту, без отдельных скиллов письма
- **Развилка 1-5** после каждого текста: stop-slop / smart-rewrite / angle-shift / style-switch / сохранить

### Скиллы (5)
- `voice-dna` — собирает голос автора из 5-15 текстов в `voice.md` (5 секций + камертон)
- `stop-slop` — чистка AI-паттернов из черновика (MIT, Hardik Pandya). Em-dash exception для русского
- `style-switch` — переписка в другом регистре. Сканирует `voice-*.md`, предлагает 2-3 под тему, может переписать сразу в нескольких для сравнения
- `smart-rewrite` — докрутка по 5 линзам (аватар-чек / жирность / глубина+озарение / обогащение / сегментация). Опциональный веб-поиск для фактов и цитат
- `angle-shift` — пересборка с нуля под одну ключевую идею. 6 шагов: прочитать → выловить «как все» → 3 кандидата → 5 проверок → топ-1 → пересборка

### Knowledge (9 файлов)
- `INDEX.md` — карта файлов
- `craft.md` — универсальная механика (~90 строк, 5 линз мяса, 9 заповедей)
- `anti-patterns.md` — что убивает текст (~60 строк, 3 типа антипаттернов + скоринг)
- `voice.md.template` — шаблон для `/voice-dna`
- `voice-universal.md` — регистр «практик в окопах» (дефолт)
- `voice-provocative.md` — «без цензуры, разговорный»
- `voice-expert.md` — «приговор индустрии»
- `voice-longread.md` — «методичка с архитектурой» (5-15К знаков)
- `voice-storyteller.md` — «герой-зеркало для pre-sell»

### Шаблоны
- `memory.md` / `failures.md` / `overrides.md` — append-only, копирайтер ведёт сам

### Интеграция
- `install.md` — машиночитаемый манифест для `/install-agent copywriter`
- Layered include в корневой `CLAUDE.md` через `@office/agents/copywriter/core.md`
- Обновление `office/AGENTS.md` и `director/core.md` (роутинг)

### Известные ограничения
- `stop-slop` оригинал на английском — для русско-специфичных AI-паттернов работает связка с `anti-patterns.md`. Em-dash для русского — мандатная типография, скилл это уважает
- Расширение `/voice-dna --extension <name>` для сборки своих регистров — заложено в roadmap 1.1.0
