# voice-learning — голос из корпуса, один файл

Ты собираешь не «описание стиля» — ты собираешь камертон, по которому
дальше пишутся ВСЕ тексты. Плохой voiceprint = слоп во всех жанрах сразу.
Методология — `knowledge/voice-learning-method.md`, читай её перед работой:
там лимиты имитации (arXiv 2509.14543), 6 осей, формат 5 секций.

Зона: ТОЛЬКО voiceprint. Тексты не пишешь — после сборки роутишь в
жанровые скиллы. Пользователю внутреннюю кухню («оси», «дистилляция»,
«voiceprint») не произносишь — он видит короткие реплики и файл.

---

## Шаг 0 — режим и адрес файла

Определи, чей голос и куда ляжет файл:

| Ситуация | Режим | Файл |
|----------|-------|------|
| Свой автор (владелец офиса), канон уже наполнен | **(а) update** — обновляешь, НЕ пересобираешь | `knowledge/voice.md` |
| Свой автор, канона нет (первый запуск) | **(б) сборка с нуля** | `knowledge/voice.md` (тот же путь — файл появляется впервые) |
| Клиент (B2B клиент владельца офиса) | **(б) сборка с нуля** | `clients/<slug>/brand/voice.md` |

Слаг клиента бери из существующих папок `clients/`; подпапки `brand/`
у клиента обычно нет — создай при первой сборке (`mkdir -p`), это
output-путь, не read-зависимость.

Проверка одна: `Read` целевого пути. Файл есть и наполнен → режим (а).
Нет или пустой каркас → режим (б).

Железно: канон — собственность владельца. В режиме (а) пересборка с нуля
запрещена без его явного запроса; любое изменение — построчной дельтой
под одобрение. Молча перезаписать канон — худший фейл этого скилла.

---

## Шаг 1 — корпус

**Оптимум — 20+ постов. Минимум — 5.** Меньше пяти — откажи честно:
«соберу скелет, не голос — принеси ещё 2-3 текста».

Три пути сбора, по убыванию удобства:

1. **telegram-mcp** (опционально; если подключён и авторизован) — выгрузи
   историю канала автора сам. Это ускоритель, не зависимость: нет MCP —
   скилл работает полностью, см. пути 2-3 и fallback-матрицу в
   `knowledge/capabilities-map.md`.
2. **Ручной экспорт** — попроси: Telegram Desktop → меню канала →
   Export Chat History → JSON или HTML, файл сюда.
3. **Копипаста** — 15-20 постов прямо в чат.

Эталон запроса фактуры (режим б):

> «Соберём голос за один заход. Кидай 15-20 своих текстов — посты,
> длинные сообщения, расшифровки голосовых. Чем разнообразнее, тем
> точнее: личное и рабочее, короткое и длинное. Можно экспортом истории
> канала (Telegram Desktop → Export Chat History) — разберу сам.»

Гейты корпуса:
- **Только своё и сырое.** Репосты, пересказы, подборки — вон. Тексты,
  писанные или приглаженные ИИ, — вон (спроси прямо: «сам писал, без
  нейросети?»). Иначе выучишь слоп как голос.
- **Разный жанр важнее объёма.** Один жанр → плоский профиль.
- В режиме (а) корпус = НОВЫЕ посты, которых канон ещё не видел
  (после даты из frontmatter канона).

---

## Шаг 2 — анализ: 6 осей, молча

Прогоняешь корпус по 6 осям из `knowledge/voice-learning-method.md`:
архитектура предложений · словарь · ритм и паузы · личностные маркеры ·
структурные привычки · анти-паттерны. Анти-паттерны — самая ценная ось:
на неформальных жанрах модель системно съезжает в generic, и держат её
именно «что автор никогда не скажет».

Три фильтра, все обязательны:
1. Наблюдение без цитаты из корпуса — удаляй.
2. Тест «применимо к любому автору» — прошло? Пустое, переписывай.
3. Молчаливая проверка: абзац собранным голосом → сравни с корпусом.
   «Всё идеально» = плохо смотрел.

После разбора — перебивка пользователю: 3-5 самых ярких наблюдений
с цитатами (не общие черты — отличия) + развилка:

> «Собрал ядро. Заметил: [наблюдения с цитатами]. Дальше два пути:
> ⚡ сразу фиксирую файл · 📦 докрутим точнее — кинь 2-3 поста любимых
> авторов с пометкой что нравится + скажи что в текстах бесит. Пара минут.»

Докрутка (опционально): чужие эталоны идут ТОЛЬКО в понимание вкуса
и анти-правила — в камертон попадают исключительно тексты самого автора.

---

## Шаг 3 — Gap Testing перед фиксацией

Напиши пробный абзац собранным голосом → сверь по тем же 6 осям → назови
вслух, где съехал в generic («ритм ровнее корпуса», «скобки пропали»).
Провал найден → правишь ПРОФИЛЬ, не абзац. 1-2 круга, не больше.

---

## Шаг 4 — дистилляция: 5 секций + камертон

Формат файла — по `knowledge/voice-learning-method.md`:

1. **Голос (ядро)** — инварианты с микро-цитатами
2. **Лексикон и графика** — слова, пунктуация, эмодзи/скобки, мат-политика
3. **Структура** — зачины, скелет, концовки, P.S./серии
4. **Анти-правила** — табу автора + generic-слоп; не короче ядра
5. **Камертон** — **3-5 цитат** из корпуса с «работает потому что…»

Лимиты имитации — закон (arXiv 2509.14543):
- Камертон — максимум 5 примеров. Больше не улучшает стиль, раздувает
  файл. Дамп 20 постов вместо дистиллята — запрещённая архитектура.
- Отбор камертона — по яркости голоса, НЕ по теме будущих текстов
  (тематический фильтр качество имитации роняет).
- Секция анти-правил обязательна и жирная — она компенсирует слабое
  место few-shot на разговорных жанрах.

Режим (а): не пересобираешь файл — выносишь дельты «появилось /
усилилось / умерло», каждую с цитатой, вписываешь в СУЩЕСТВУЮЩИЕ секции
канона (его структуру не ломать — «1. Голос» там объединяет секции 1-3).

---

## Шаг 5 — приёмка и фиксация

1. **Тест подмены** — вслух: «текст этим голосом в чужом канале
   подписчик отличит?» Профиль, по которому нельзя ответить «да», —
   не готов.
2. **Показ владельцу**: режим (б) — файл целиком; режим (а) — только
   дельты построчно («вот что вписываю, ок?»). Пишешь ТОЛЬКО после «да».
3. Frontmatter файла: дата, источник корпуса (сколько постов, откуда),
   кто одобрил.
4. Честное ожидание, если спросят про «неотличимость»: клон частично
   детектируем всегда — цель «попадание в канал автора», не больше.
5. Память: запись в `memory.md` (что за голос, сколько корпуса, что было
   сложным); фейл (корпус с ИИ-полировкой прошёл фильтр, владелец
   забраковал профиль) → `failures.md`.

Дальше — передача: «Голос собран. Теперь любой текст — жанровым скиллом
(`tg-post` / `threads` / `article`), они читают этот файл сами.»

Ревизия потом: владелец говорит «уже не звучит как я» или корпусу профиля
больше ~полугода → предложи update-заход, не жди команды дословно.

## Примеры (Input → Output)

**Input:** «Обнови мой голос — за последние два месяца я стал писать
по-другому, посты в канале свежие.»
**Output:**
```
Режим: update канона knowledge/voice.md (существует, наполнен).
Корпус: посты после 2026-06-18 (дата канона). telegram-mcp не авторизован —
кидай экспорт истории (Telegram Desktop → Export Chat History) или 15-20
свежих постов сюда.
[корпус получен → 6 осей → дельты]
Дельты к канону (3, все с цитатами):
1) усилилось: сериализация — «об этом завтра» в 6 постах из 18 → в секцию
   «Структура»;
2) появилось: «нейрочелядь» как тёплое про агентов — «моя нейрочелядь
   опять всё сделала» → в лексикон;
3) умерло: `!!!!` — ни одного вхождения за 2 месяца → пометка в графике.
Вписываю эти три строки в канон? Пересборку не делаю — остальное живо.
```

**Input:** «Голос клиента: вот 25 постов из канала Тамары, собери ей
tone of voice для лендинга и рассылок.»
**Output:**
```
Режим: сборка с нуля → clients/tamara-sedova/brand/voice.md
(папки brand/ не было — создал).
Корпус: 25 постов — норм (порог 20+). Фильтр: 2 поста выкинул — репост и
текст с ИИ-полировкой («В современном мире каллиграфия…» — не её рука).
Ядро (яркое, с цитатами): «пишет как говорит за чашкой — обрывает фразы
("Ну и вот."), уменьшительные без сюсюканья ("буковки", "хвостики"),
никогда не продаёт в лоб — только показывает процесс».
Gap Testing: пробный абзац съехал в глянец — вернул обрывы фраз в ядро.
Файл: 5 секций + камертон 4 цитаты. Показываю целиком — после «да»
записываю и передаю: тексты лендинга пойдут по core-роутингу с этим
файлом как законом голоса.
```
